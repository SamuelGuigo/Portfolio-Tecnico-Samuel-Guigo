# Infrastructure Monitoring with Zabbix & Grafana

**Role:** Monitoring & Infrastructure Engineer  
**Type:** Monitoring / observability case

## Objective

Centralize infrastructure visibility across servers, network devices and services using Zabbix, Grafana and standard telemetry methods.

## What I work with

- Zabbix Server and agents
- SNMP monitoring
- network-interface monitoring
- host availability
- CPU, memory and storage metrics
- service health
- triggers and alerts
- low-level discovery
- dashboards
- Grafana visualization
- performance and capacity analysis

## Troubleshooting focus

Monitoring is useful only when the collected data is reliable.

I routinely work on issues such as:

- unsupported items;
- discovery errors;
- incorrect or volatile SNMP indexes;
- missing interface counters;
- noisy triggers;
- incomplete coverage;
- agent communication problems;
- misleading dashboards.

## Architecture approach

The monitoring model separates:

- **availability** — whether a host, service or interface is reachable;
- **performance** — whether resources are behaving normally;
- **capacity** — whether utilization is approaching operational limits;
- **quality/degradation** — whether counters indicate an emerging issue before an outage.

## Technologies

## Result

The architecture provides a centralized operational view that helps reduce troubleshooting time and makes infrastructure degradation easier to identify.
