# Public Portfolio Sanitization Policy

This repository contains public, sanitized technical case studies.

## Never publish

- credentials, passwords, API tokens or private keys;
- internal IP addresses or private DNS names;
- customer-identifying hostnames;
- SNMP communities;
- serial numbers and asset tags;
- customer names unless publication is explicitly authorized;
- exact sensitive topology details;
- confidential screenshots;
- internal ticket, contract or project identifiers;
- vulnerability details tied to an identifiable customer environment.

## Publication rules

Public cases preserve the technical value of the work while removing identifying data.

When a project is not fully completed, the case must clearly distinguish among:

- implemented;
- validated;
- in progress;
- planned;
- pending acceptance.

Labs must be identified as labs. Architecture documents must not be presented as production deployments.

## Purpose

The goal is to demonstrate troubleshooting methodology, infrastructure knowledge, documentation quality and engineering decisions without exposing customer or employer-sensitive information.
